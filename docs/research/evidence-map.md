# Карта доказательств

> Документ подготовлен с использованием ИИ по журналам исследования от 2026-10-31. Он связывает выводы с источниками из [sources.md](sources.md), но не повышает уровень подтверждения и не заменяет новую проверку.

## Уровни подтверждения

| Уровень | Значение |
|---|---|
| Прямое наблюдение | Получено с конкретного устройства владельца |
| Подтверждено для сохранённых файлов | Локальное побайтное сравнение или хеш; не доказывает полноту NAND |
| Документация производителя | Официальный datasheet; не является наблюдением устройства |
| Статический разбор кода | Изучение исходников или отчётов; не запуск на устройстве |
| Согласующееся объяснение | Механизм подходит к наблюдению, но не идентифицирует vendor-код |
| Гипотеза | Правдоподобное объяснение без достаточного подтверждения |
| Не установлено | Проверка не дала подтверждённого результата |
| Только направление | Материал предложен для будущего изучения, не является основанием |

- Что перечисленные методы проверены на `YNDX-00020`.
- Что публичный драйвер Amlogic является исходниками прошивки Яндекса.
- Что гипотеза `page127` доказана.
- Что сохранённые файлы образуют полный физический дамп NAND.
- Что восстановление BL2 или устройства проверено.
- Что наличие внешней копии заменяет независимое повторное чтение NAND.
- Что источник поддерживает данный инструмент или одобрен его авторами.
- Что отсутствие commit в журнале можно заменить текущим HEAD репозитория.

## Правила повышения уровня

1. Новый уровень должен опираться на новое наблюдение или документ, а не на повторение формулировки.
2. Для изменения «гипотеза» → «подтверждено» нужна воспроизводимая проверка на соответствующем устройстве или однозначный первоисточник.
3. Для изменения «не установлено» → «подтверждено» нужна проверенная процедура, а не косвенное сходство.
4. Для vendor-кода нужна идентификация конкретной ревизии и артефакта, а не сходство поведения.
5. Даты, ревизии и ограничения должны сохраняться при обновлении записи.
