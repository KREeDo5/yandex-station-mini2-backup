# Предварительные требования

## Обязательный чек-лист

- [ ] У вас есть физический доступ к устройству и понимание рисков root/NAND.
- [ ] Устройство — именно YNDX-00020 с проверенной прошивкой; device tree должен отдавать читаемую модель. Неизвестная модель блокирует запуск в v0.1, а строка семейства Mini 2 не доказывает артикул.
- [ ] Root SSH уже настроен. Этот проект не получает root.
- [ ] SSH работает по ключу на порту 2222.
- [ ] Host key устройства проверен независимым способом и добавлен в `known_hosts`.
- [ ] На рабочем компьютере macOS и Python 3.11+.
- [ ] Есть системный `ssh`.
- [ ] На колонке есть `nanddump` с `--bb=padbad` и `--omitoob`.
- [ ] На колонке есть `tar`, и его help показывает `-c`, `-f` и `-C`.
- [ ] Достаточно свободного места локально.
- [ ] Питание и сеть стабильны.
- [ ] Вы не публикуете результаты без проверки на секреты.

## SSH

Инструмент использует:

- `BatchMode=yes`;
- `PasswordAuthentication=no`;
- `PubkeyAuthentication=yes`;
- `IdentitiesOnly=yes`;
- `StrictHostKeyChecking=yes`;
- `-T` (без PTY).

Инструмент **не**:

- добавляет неизвестный host key;
- использует `StrictHostKeyChecking=no` или `accept-new`;
- копирует приватный ключ;
- запрашивает пароль;
- запускает `shell=True` локально;
- интерполирует host/port/user в произвольную shell-команду.

Если `known_hosts` не настроен, `check` завершится с объяснением. Проверьте fingerprint устройства вне SSH (например, по документации/экрану/физической метке, если это возможно) и добавьте ключ сами. Не отключайте проверку host key ради удобства.

Приватный ключ должен быть обычным файлом. Инструмент не читает его содержимое и не выводит его. Слишком открытые права могут вызвать предупреждение или отказ OpenSSH.

## Python

Нужен Python 3.11+. Проверка:

```sh
python3.12 --version
```

Обёртки ищут подходящий интерпретатор. Можно задать:

```sh
MINI2_PYTHON=/path/to/python3.12 scripts/check.sh --help
```

Сторонние runtime-зависимости не нужны. `pip install`, `brew install` и `sudo` инструмент не запускает.

## Утилиты на устройстве

`check` проверяет наличие `nanddump` и `tar`, строки `--bb=padbad` и `--omitoob` в `nanddump --help`, а также опции `-c`, `-f` и `-C` в `tar --help`. Это проверка доступной команды, а не запуск записи или создание файлов на колонке. Разные версии `nanddump` могут иметь разный синтаксис; нельзя предполагать его одинаковым.

Если `tar` отсутствует, backup завершится ошибкой. Инструмент не устанавливает утилиты на колонку.

## Место на диске

Ориентир для всех разделов:

| Раздел | Размер |
|---|---:|
| mtd1 tpl | 2 097 152 |
| mtd2 boot | 10 485 760 |
| mtd3 system | 83 886 080 |
| mtd4 nv | 1 048 576 |
| mtd5 bkupgrade | 110 362 624 |
| mtd6 recovery | 52 166 656 |
| **Итого образы** | **260 046 848 байт (~248 MiB)** |

Плюс tar `/bkupgrade` (размер заранее неизвестен, ориентир — размер раздела `mtd5` и запас) плюс отчёты и журналы. Инструмент проверяет свободное место перед каждым артефактом и всё равно обрабатывает `ENOSPC`.

## Сеть и питание

Не запускайте backup в нестабильной сети или при нестабильном питании. Обрыв SSH приведёт к ошибке и сохранению `.part`; автоматического продолжения нет.

## Приватность

Отчёты и архивы могут содержать имена устройства, пути, хеши и содержимое `/bkupgrade`. Не публикуйте их без ручной редакции. См. `SECURITY.md`.
